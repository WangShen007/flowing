# 飞书任务归属规则

企业模式的任务写入在 CLI 执行入口校验，不以模型文本、搜索结果缓存或本地历史记录认定所有者。

| 身份/关系 | 修改内容、分配人员 | 标记完成 | 删除 |
|---|---|---|---|
| 当前用户是任务创建者 | 允许 | 允许 | 单任务确认后允许 |
| 当前用户仅是执行人 | 拒绝 | 允许 | 拒绝 |
| 关注者或其他普通用户 | 拒绝 | 拒绝 | 拒绝 |
| 网站 admin，任务位于明确配置的团队清单中 | 允许 | 允许 | 单任务确认后允许 |
| admin 的管理清单之外 / lead | 不享有额外权限 | 按创建者/执行人判断 | 不享有额外权限 |

以上“允许”仅表示通过网站策略，飞书自身资源权限仍必须允许。不会借用其他人的 token 或切换机器人身份。网站角色不自动同步飞书职级。

## 管理范围配置

部署者在后端环境配置 `FEISHU_MANAGED_TASKLIST_IDS`，值为逗号分隔的团队任务清单 GUID；重启服务生效。默认留空，管理员仅能按本人创建者/执行人身份操作。不得填写任意全部资源通配符。未自动指定用户现有清单为管理范围。

示例：`FEISHU_MANAGED_TASKLIST_IDS=<经过确认的团队任务清单GUID>`。

这一范围是本网站 admin 角色的共同管理范围，不是企业租户全部任务。需要不同管理员管理不同项目时，应进一步引入逐管理员清单配置，不能把默认范围扩大为全租户。

## 执行与审计

- 新增原生任务详情读取、删除操作。已有 `task:task:read` 和 `task:task:write` 足以覆盖当前 CLI 声明，不需要为此申请宽泛的企业管理身份。
- 修改、分配、完成和删除前实时请求 `task tasks get`，固定 `user_id_type=open_id`，使用当前用户 token。
- 校验详情 GUID、creator、members（assignee）和 tasklists；读取失败、身份缺失、目标不明确均拒绝。
- 批量修改在任何写入前检查全部目标；飞书后续网络/API失败仍可能造成部分完成，并非分布式事务。
- 确认等待结束后才执行归属校验；读取之后再次检查角色和 scopes。飞书读取和修改不是原子事务，最终资源 ACL 由飞书继续校验。
- `task_permission_audit` 存储账号、目标 GUID、动作、允许依据或 denied、时间；它记录授权决策，不等同于业务执行成功。执行结果仍见原有 execution records/agent tool receipts。
- 删除仅支持当前 LangGraph 确认流程。模型不能设置 `yes`，后端收到具体写操作确认后才附加 CLI 的 `--yes`。直接命令、legacy 路径不能自行启用删除。
- 定时执行不能复用常规预授权自动删除。未确认则暂停，不执行删除。

文档和多维表格继续沿用飞书资源 ACL，**没有把任务创建者规则泛化成所有文档/表格记录的规则**。多维表格中的“完成”是字段更新，与飞书任务的完成动作不同。

本轮没有创建、修改、删除任何真实飞书任务，验证使用隔离测试数据和模拟接口。上线还应使用不同企业账号在专用测试清单中验收。
