  the operation carries a JSON string payload. The full exact payload remains
  visible in assistant text/raw parameters. It was manually inspected before
  approval. This is a UI acceptance failure, not a wrong-target write.
- Video meeting initial request explicitly required 2026-09-09 12:00–12:10
  Asia/Shanghai, no extra attendees/messages/reminders. Model generated native
  calendar events create with timestamp 1788897600 / 1788898200, actually
  04:00–04:10 Asia/Shanghai. The UI displayed the converted times correctly.
  The wrong plan was NOT approved or executed. Planning active time 41.046s.
- When instructed to correct that time, the model finished with clarification
  and claimed a corrected plan was awaiting confirmation, but commands and
  executed_commands were empty and no confirmation card appeared. This is a
  false planning-status response; no meeting had yet been created.
