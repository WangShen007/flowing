# 个人微信 / Telegram 私人助手

## 使用方式

员工登录自己的网站账号，打开「账号与权限 → 我的微信 / Telegram 助手」，扫码并在手机确认。
如微信要求验证码，在网站输入手机显示的验证码。扫码成功后，还要在原网站账号点击「是我本人，确认绑定」。
二维码 5 分钟过期，不要转发给他人。Telegram 扫码打开机器人后须点击 Start。

每个网站账号可各绑定一个个人微信 ClawBot 入口和一个 Telegram 私聊身份。
两种渠道分别保留会话上下文，共享该员工本人的飞书授权和已确认工作流记忆；不会混入其他员工的会话。
同一员工在网站会话列表中可以看到自己的机器人会话。当前支持纯文字，不接收群聊、图片、语音或文件任务。
这不是接管个人微信的所有好友会话，也不读取员工的其他微信聊天记录。

写操作依旧经过既有 LangGraph 中断、权限校验和执行收据流程：机器人给出具体操作及
`/confirm <随机确认码>`，只能在原绑定私聊中、10 分钟内使用一次。过长的操作预览须在网站确认。
飞书授权操作仍在网站完成。默认时间语义沿用北京时间。

## 部署

使用项目现有后端和前端部署流程，安装新增的 `qrcode>=8.2,<9` 依赖，重新构建前端并重启后端。

配置项：

- `BOT_CHANNELS_ENABLED=true`：启用渠道和后台收件处理；设为 false 并重启可整体关闭。
- `FEISHU_TOKEN_ENCRYPTION_KEY`：沿用既有 32 字节 Base64 加密密钥；必须有效。
- `TELEGRAM_BOT_TOKEN`：部署管理员在服务端环境中配置专用 BotFather 机器人令牌，不应发送到聊天或提交 Git。
  留空时 Telegram 入口显示未配置；不影响微信扫码。

微信无需手动提供机器人令牌；扫码获取的凭证由服务端加密保存。
Telegram 使用官方 getUpdates 长轮询：专用机器人不能同时挂在别处轮询或配置 webhook。
本程序不会替你删除已有 webhook。服务器须能连接 `api.telegram.org` 和微信 iLink HTTPS 接口。
网站生产部署应使用 HTTPS；机器人不需要公网 webhook，也不需要额外安装 OpenClaw。

目前后台为**单主机 SQLite 部署**：进程间文件锁选出一个渠道运行器，多个 ASGI 进程不会重复轮询。
不支持多个主机/NFS 共用数据目录。水平扩容前应改成具备租约和事务队列的集中式数据库。

## 隔离和可靠性

- 绑定、会话、确认码由服务端解析的身份关联，不信任消息正文中的网站用户 ID；管理员接口不提供他人聊天查看能力。
- 微信只接受已扫码绑定的 `ilink_user_id` 的最终私聊消息；Telegram 校验 private chat 和发送者 ID 一致。
- 不允许新绑定覆盖已有账号绑定。二维码和凭证不发给其他员工；后端凭证加密附加认证数据包含网站账号、用途及绑定 ID。
- 入站事件先落 SQLite，通过绑定 ID + 平台事件 ID 去重，再推进平台游标；每个绑定最多排队 20 条。
- 最多同时执行 4 个机器人任务，同一员工的两个渠道串行处理。复用网站原有任务准入限制。
- 解绑会撤销排队消息、确认码和该机器人会话的待恢复检查点。员工停用时与账号状态变更原子撤销绑定。
- 执行上下文在每次后续飞书工具调用前重查绑定。已提交到飞书的操作不能靠解绑撤回。
- 运行中崩溃标记 `execution_unknown`，发送中崩溃或网络送达不明确标记 `delivery_unknown`，均不自动重放。
  已持久化但还没开始发送的结果可继续投递，不重跑 AI。未知结果数量显示在本人的渠道状态中。
- 轮询失败按上限 60 秒退避，其他员工的渠道独立运行；界面显示后台心跳和渠道状态。
- 去重/暂存记录保留 7 天，正常聊天历史按原网站策略保留。备份数据库及加密密钥应按敏感数据管理。

**隐私边界：** 网站管理员身份不能读取他人聊天，但服务器 root、数据库和密钥持有者仍具有技术读取能力。
聊天还会经过对应消息平台和当前配置的模型服务。本实现不是端到端加密承诺。

## 验证状态（2026-09-08）

- 后端 368 项测试全部通过（原有 346 项 + 新增 22 项），覆盖渠道身份隔离、重复事件、确认码、绑定状态机、停用撤销、串行/并行调度等。
- 浏览器 22 个回归场景通过，包含二维码、验证码、显式本人确认、解绑、未配置 Telegram 的状态与原有聊天/权限功能；前端构建和新增 Python 文件 Ruff 检查通过。
- 微信真实 `get_bot_qrcode` 接口已成功返回二维码；未替员工扫码授权。
- 微信真实收发消息、真实飞书写入确认仍需本人扫码后验证；Telegram 真机链路仍需配置 Bot Token。
- 此阶段没有声称完成多员工真机压力测试或多主机部署验证。
